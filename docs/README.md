# OctoAcme Project Management Docs

These documents give new teammates a concise overview of how OctoAcme manages work from idea to improvement. The process is intentionally lightweight but structured around a clear lifecycle: initiation, planning, execution, release, and retrospective follow-through. Work starts with a project one-pager that captures the problem, goals, success metrics, stakeholders, timeline, risks, and proposed roles, then moves into planning through backlog creation, estimation, acceptance criteria, Definition of Done, milestone mapping, and dependency tracking.

During execution, teams use a shared project board with stages such as Backlog, Ready, In Progress, In Review, QA, and Done so delivery status stays visible and blockers surface early. Project Managers coordinate schedules, risks, documentation, and stakeholder updates; Product Managers define outcomes and priorities; Developers build and estimate the work while flagging technical risks; QA contributors validate acceptance criteria; and stakeholders provide input, decisions, and approvals. Across these roles, OctoAcme emphasizes clear ownership, transparency, and cross-functional collaboration over heavy process.

Communication is built into the operating model through regular standups, weekly PM and Product syncs, delivery reviews, sprint or milestone demos, and monthly stakeholder updates. Risks and dependencies are tracked in a simple register, reviewed regularly, and escalated from the team to PM, Product Lead, and sponsor when needed. The docs also promote a shared source of truth for status updates and consistent templates for weekly reporting and incident communication.

Quality assurance is treated as part of everyday delivery rather than a final checkpoint. Teams are expected to use unit testing for new logic, integration testing where relevant, end-to-end smoke testing for critical flows, CI-based linting and security scans, and manual QA when needed for feature acceptance. Small pull requests, issue-linked PR descriptions, automated checks, reviewer approval, staging validation, rollback planning, post-deployment verification, release notes, and retrospectives all help OctoAcme improve quality while continuing to ship.
