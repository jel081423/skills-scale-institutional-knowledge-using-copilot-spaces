# OctoAcme — Role Engagement Checklist

## Purpose
Provide a lightweight checklist for confirming which roles need to participate in planning, execution, release, and retrospective activities.

## How to use
- Copy this checklist into the project one-pager, planning doc, or kickoff notes.
- Mark the roles that are active for the initiative.
- Add the named owner for each active role and any required approvals or handoffs.

## Role Roster
- [ ] Developer owner named
- [ ] Product Manager owner named
- [ ] Project Manager owner named
- [ ] QA / Test Engineer owner named (if active)
- [ ] Engineering Manager / Technical Lead owner named (if active)
- [ ] UX / Product Designer owner named (if active)
- [ ] Executive Sponsor / Business Stakeholder owner named (if active)
- [ ] Support / Customer Success owner named (if active)
- [ ] Security / Compliance reviewer named (if active)

## Planning Checklist
- [ ] Confirm which roles are active for this initiative
- [ ] Document decision owners for scope, schedule, and technical trade-offs
- [ ] Identify approvals or reviews needed before execution starts
- [ ] Capture customer, support, security, or design dependencies early

## Execution Checklist
- [ ] Confirm who reviews backlog changes, blockers, and dependency shifts
- [ ] Involve QA for high-risk stories before they reach release preparation
- [ ] Pull in design, support, or security when implementation changes affect their area
- [ ] Escalate cross-team or business-impacting issues through the named PM / sponsor path

## Release Checklist
- [ ] QA confirms test results or open-defect decision
- [ ] Support / Customer Success confirms enablement and communication needs
- [ ] Security / Compliance confirms required reviews are complete
- [ ] Sponsor or stakeholder approvals are recorded when needed

## Retrospective Checklist
- [ ] Invite the roles most involved in delivery or release friction
- [ ] Review whether role ownership or handoffs were unclear
- [ ] Convert role-related process gaps into named action items
